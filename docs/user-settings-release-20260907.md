# User Settings and login release — 7 September 2026

Security and Audit Logs are under User Settings. The previous workspace URLs redirect to the new sections. Password accounts may have at most two active device sessions across workspaces. A third sign-in displays a modal listing active devices and lets the user end a selected session before continuing. The server serializes admission, refresh and revocation under a user row lock. Revoked access and refresh tokens fail immediately; an open workspace checks its session every ten seconds and on focus.

The login form uses consistent 44px controls and removes the Google Workspace coming-soon button and divider. Sign-in now reports submission, session confirmation and navigation progress. It confirms the browser cookie session before opening the workspace with a new document request, avoiding the previous client navigation/refresh race. Requests have bounded timeouts and display retryable network, server, malformed-response and missing-session errors. A visible Open workspace link remains available if navigation stalls. Session redirects explain whether the session ended or the service is unavailable.

Validation: 22 backend auth tests, including PostgreSQL concurrency and revocation cases; nine login/client tests; scoped lint and type checking; frontend and backend production builds. Local browser checks exercised selected-device logout, revoked-tab logout, settings navigation and mobile sizing. Staged and public production browser checks passed sign-in feedback, two successful device logins, a blocked third login, the modal, immediate access-token rejection after logout, admission after freeing a slot, User Settings and 390px mobile controls. Two unrelated pre-project sidebar tests retain an existing navigation-count mismatch.

Deployment is live at https://iglo.wodana.ai/login. Images `wodana-web:20260907-user-settings` and `wodana-core:20260907-user-settings` use ports 13070 and 18030. Integration API port 18002 uses the existing intelligence image configured to validate user sessions through the new core. Existing database, storage and background worker remain in place. No schema migration was required. Production smoke checks passed the Iglo and admin logins, public landing page, client portal and API readiness endpoint.

Release files are in `/opt/wodana/releases/20260907-user-settings`. The production source archive was used as the base and only the scoped auth/settings files were overlaid; package locks are unchanged. Linux runtime dependencies come from the preceding production images. Previous services are retained; `rollback.sh` restores the preceding nginx upstreams.
