# MFA web connection — 15 September 2026

The Wodana staff login and User Settings screens are connected to the verified Business Core MFA
contract. This is generic SaaS behavior driven by each customer account's security policy; it is not
specific to Palm Living or one organization.

## Connected behavior

- Password login stops at a five-minute authenticator or recovery-code challenge when MFA is active.
- Challenge tokens remain in short-lived HttpOnly cookies and are never exposed to browser code.
- Required users receive the configured enrollment deadline, can defer only during the grace period,
  and must acknowledge the one-time recovery codes before entering the workspace.
- User Settings shows enabled, required, enrollment, and remaining-recovery-code state.
- Recovery-code replacement and optional disablement first require a fresh authenticator or recovery
  code. MFA required by account policy cannot be disabled in the interface or backend.
- Access-token replacement after enrollment and step-up happens in same-origin server routes. A
  rotated refresh token is used if the original access token expires during a security action.
- Device-limit handling remains compatible with MFA: the chosen session identifier is kept in a
  short-lived HttpOnly cookie and applied only after the next factor succeeds.
