# Slice 1C — internal document RFAs and project grid refinement

User-requested visual change: full vertical/horizontal cell lines and an enclosing table viewport border; compact copy; distinguish state, quantities and primary actions. Opt in the existing shared DataGrid for project tables. This explicitly supersedes the older no-table-borders guideline for these screens, without changing CRM tables or the application shell.

Journey: Project → Approvals → New RFA → select controlled document revision, responsible reviewer and due date → save draft → submit → start review → approve, return or reject. Submit freezes document and scope evidence. Submitter cannot approve their own request; only the named active reviewer with projects.review may decide. A planner may withdraw with a reason. A returned/rejected/withdrawn request can be revised into a new linked request; old evidence/decisions remain immutable. Approved requests cannot be revised in place: use a new controlled document revision.

Fields: stable ID; optimistic version; document ID; named reviewer membership ID; due date; instructions; state; creator/submission actor and times; server-captured document and released-scope snapshot; revision-of ID; event history with actor/time/decision/reason. First slice is internal only. No conditional approval, delegation, multi-reviewer policy or portal publishing is implied.

API: existing project command endpoint and project-level requestId/revision protection. Commands rfa_save, rfa_submit, rfa_review, rfa_decide, rfa_withdraw, rfa_revise. Draft edits require projects.manage; decisions require projects.review and designated reviewer identity. A document with an RFA must use the RFA command for approval; legacy document_status cannot bypass it. One open request per document, frozen submitted content, stale-source rejection, no self approval, reason required for return/reject/withdraw/revise. Approval updates the canonical document's approval state and applies the existing superseded-drawing work block; it does not release the project, purchase, publish externally or book a team.

Queue and readiness: canonical RFA records project into project Approvals and the existing project next-action pulse with named owners and stable approval deep links. Active submitted/in-review/returned/rejected requests and unresolved revision drafts block related scope readiness/start until approved or explicitly withdrawn. Draft requests that have never been submitted do not impose a release requirement. Global cross-project task-board aggregation and client/supplier review are later integrations, not duplicate local task records.

Verification: transition matrix, role/identity checks, source snapshot/staleness, optimistic version, legacy bypass prevention, return/revision history, scope readiness and next-action links; UI drafts/errors/action availability; desktop/mobile grid lines and keyboard/RTL checks. Local fixtures only, no deployment or customer mutations.

## Local implementation result

Project DataGrid instances now opt into full grid boundaries, with an enclosing viewport border, shaded headers, state badges and visible row actions. Quantity screens have shorter copy and emphasized quantities. CRM table defaults are unchanged.

Project → Approvals now provides Open requests, My reviews and All requests. The request inspector uses the existing controls and supports all commands above. Documents with RFAs link back to the exact request. Draft documents can now be edited and linked to released BOQ items, completing the return → correct document → revise RFA → resubmit path. Reviewer choices use current review permissions; submission rechecks membership/authority. Submitted snapshots capture document metadata, released scope and available managed attachment hashes. External URL bytes are not downloaded or frozen by this slice; their controlled reference/revision is recorded.

Verification: 101 backend tests across six relevant suites (including 22 RFA cases); 54 component tests across six UI suites; web and backend typechecks; scoped lint. Eight desktop/mobile browser checks passed across navigation, quantity planning and RFA review-to-approval. Browser fixtures intercept project API calls; no live customer database writes. Grid dividers and all four viewport borders checked, keyboard/RTL behavior exercised, mobile/desktop screenshots inspected. Persistence remains the existing project command transaction and revision/idempotency mechanism; a deployed database integration test was not performed.

Outstanding: cross-project task-board aggregation; portal-published client/supplier RFA decisions; multi-reviewer/delegation and conditional-approval policies; aftercare approvals. This is the internal document RFA slice, not completion of every approval type in the 30-section blueprint. No production activation or deployment.
