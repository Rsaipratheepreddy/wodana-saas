# Slice 2E — installation batches and partial acceptance

An assigned site reporter/planner creates named batches from independently approved site output. Sum of non-cancelled batches cannot exceed approved output. Each batch has a server id, name, quantity/unit, creator/time, QC state, reviewer/evidence history and optional file snapshots. A different authorized reviewer passes or returns the batch for rework. Reinspection retains earlier decisions. Unpassed batches may be cancelled by a planner; passed batches require a future controlled reversal.

The existing task dialog creates a batch and displays its QC actions. Full-task QC cannot bypass batch QC. Reporting corrections cannot reduce approved output below allocated batch quantities. Partial client packs explicitly select passed batches from the chosen area/package; packet quantities derive from those batches, not editable totals. Different passed batches for one task may occupy different packs. The same batch cannot be ready/accepted twice, and full-task packs cannot overlap partial ones. Returned packs release reservation. Both signed and portal acceptance recheck current batch status and identity.

Package/area closeout documents, affected snag, commissioning and technical query controls still apply conservatively at task scope. Batch handover does not finish the rest of the task or project. Warranty remains tied to accepted handover; serial-level assets, within-batch acceptance, post-acceptance reversals and fine-grained snag/commissioning attribution remain outside this slice.

Validation: focused domain tests cover distinct batches on one unfinished task, both signed and authenticated-portal acceptance, duplicate reservations, excess batch quantities, independent QC, rework history, blocked full-task QC bypass, protected output corrections and final-account closure. A connected receipt/material/site/batch/acceptance scenario is included. Four browser checks cover desktop/mobile, keyboard, RTL and direct evidence upload; screenshots inspected. Component tests cover action permissions and upload recovery. No production enablement or live database integration performed.
