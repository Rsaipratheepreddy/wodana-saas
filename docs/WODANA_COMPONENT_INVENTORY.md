# Wodana web component inventory

**Audited:** 17 September 2026 · **Purpose:** CP00.3, before changing the internal control-plane UI.

This is an inventory of the code that exists, not a claim that all feature screens already use it. The canonical public import is `@/design-system`, exported by [`apps/web/design-system/index.ts`](../apps/web/design-system/index.ts). It is a custom React Aria Components kit with TanStack Table/Virtual for lists and Lucide for icons. [`apps/web/components/ui`](../apps/web/components/ui/index.ts) is an older, much smaller kit (`DataTable` included); only HRMS still imports it directly. New internal-portal work must compose the canonical kit, not mix the two or copy feature-local controls.

## How the existing table works end to end

1. Define `DataGridColumn<Row>[]` using TanStack's `accessorKey`/`accessorFn` or `id`, `header`, optional `cell`, `size`, and `meta` (`primary`, `align`, `filterOptions`, `mobileHidden`, `editable`, `validate`, `editor`, `renderCell`). See [`crm-customers.tsx`](../apps/web/components/crm/crm-customers.tsx) for a production column definition.
2. Pass `ariaLabel`, `columns`, `data`, `getRowId`. The toolbar supplies global search, sortable/filterable column controls, column visibility, saved views and export; sort/visibility state persists in the URL when `persistKey` is supplied. The grid has TanStack client sorting/filtering, optional external search, client or `manualPagination`, `page/pageCount/onPageChange`, and virtualization after `virtualizeAfter` rows.
3. Row selection is `selectable` by default; `bulkActions(selectedRows)` appears when rows are selected. For a row click use `onRowAction(row)` or `renderInspector(row, close)` with `getInspectorTitle`; a row-specific action menu belongs in a `DataGridColumn` cell with shared `IconMenuButton`. There is no separate built-in `rowActions` prop.
4. `isLoading` renders shared `Skeleton`, `error` renders `ErrorState`, and zero filtered rows render `EmptyState` with `emptyTitle/emptyDescription`. `footerActions` supports cursor “Load more”. CSV export escapes spreadsheet formula prefixes. [`data-grid.stories.tsx`](../apps/web/design-system/patterns/data-grid.stories.tsx) demonstrates selection, bulk change, inline edit, saved views, inspector, subtable and large-data virtualization.
5. The grid's complete outer border comes from [`record-tables.css`](../apps/web/design-system/styles/record-tables.css). Keep it; the user explicitly wants an end border around tables. Use one border system and quiet row separators, not nested card borders.

## Inventory findings and gate for CP00.4

- [`apps/web/app/internal/portal.tsx`](../apps/web/app/internal/portal.tsx) originally bypassed the canonical kit with one raw table, 11 raw buttons, six raw inputs and four raw selects. CP00.4 replaced these with the shared DataGrid, form controls and shell; the numbers above are a pre-change baseline, not the current portal state.
- A repository-wide baseline over feature `.tsx` files (excluding the older `components/ui` library) finds 22 raw `<table>`, 458 `<button>`, 225 `<input>`, 46 `<select>`, and no raw `<dialog>` occurrences. The requested empty grep check therefore **does not pass yet**; a whole-product migration is a separate tracked task and must not be claimed complete from the portal slice.
- No canonical `PageHeader` or schema-driven form adapter exists. Use `Container`/`Surface`/`Heading` and existing `Form`/field controls first; if a recurring page header or validation adapter is genuinely needed, add it once in the design-system package and test it. Do not create `Button2`, `NewTable`, `CustomCard`, feature-local control forks, or className overrides of component internals.
- The design-system README's green/aqua guidance is out of date relative to the approved neutral/indigo product direction. Do not reintroduce green primary actions or broad gradients while composing the portal.
