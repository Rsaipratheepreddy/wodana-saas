## How to resume after any context reset

1. Read this board, the [blueprint](WODANA_PRODUCT_BLUEPRINT.md), [architecture source of truth](architecture/00-source-of-truth.md), relevant domain docs, and repository `AGENTS.md` files. Inspect `git status` before editing; the working tree may contain user work.
2. Select the first unchecked task whose dependencies are complete. Verify existing code and tests; never infer completion from a prior narrative, an API route, a UI tab or a provider connection record.
3. Implement one vertical slice through contract/domain/API/web/native mobile (where staff action belongs), then its empty/error/permission states and tests. Keep current routes working or provide migration redirects.
4. Record the exact test command and result, affected files, remaining risk and evidence link in the log below. Only then check off the task. If scope changes, update the blueprint and this board before proceeding.
5. Do not deploy, change Palm live data, invite the wider client team, or claim provider delivery without a separate authorized release and real verification. Synthetic local/clone data is the default.

### Definition of done for every product slice

- [ ] Business rule and owner are explicit; contracts and version/idempotency behavior are defined.
- [ ] Tenant isolation, legal-entity/branch scope, permissions, audit and failure/retry paths are tested.
- [ ] Shared web components/design tokens are reused; mobile action is implemented natively when field/staff work needs it.
- [ ] Loading, empty, error, validation, accessibility, light/dark, responsive and long-content states are reviewed.
- [ ] Automated tests and a real end-to-end path pass with synthetic data; outputs and screenshots are attached to the evidence log.
- [ ] Connected provider capabilities are verified by a real receipt; unconnected ones are honestly labeled unavailable.
- [ ] Documentation and task status match the code. No credentials, MFA codes or personal client data enter test artifacts.
